# ميزانية سياق Hermes في SULY

## الهدف

تقليل النص الاختياري الذي يحقنه SULY في أول طلب تشغيل Hermes؛ لأن harness خارجي قد يعيد استخدام هذا السياق في دورات النموذج المتتابعة. هذا التعديل لا يغيّر upstream Hermes ولا يدّعي منع إعادة إرسال السياق داخل Hermes.

## حدود السياق الحالية

| العنصر | الحد |
|---|---:|
| السياق الإضافي الكلي مع الطلب الأصلي | 12,000 حرف |
| سجل المحادثة السابق | 4,000 حرف |
| الرسائل المسترجعة للمحادثة | 12 رسالة كحد أقصى |
| نص الرسالة الواحدة | 1,000 حرف |
| بايتات ذاكرة المستخدم المسترجعة | 8 KiB |
| ذاكرة المستخدم المضمنة | 2,000 حرف |
| الموافقات على المهارات المسترجعة | 12 حزمة |
| المهارات المضمنة | 4,000 حرف |

تظل رسالة المستخدم الأصلية كما هي. عندما تستهلك الرسالة الأصلية الميزانية، يتوقف السياق الإضافي بدل حذف/قص الطلب. تُختار الرسائل الأحدث أولًا، ثم تُعرض بترتيب زمني، مع بقاء owner/conversation/time filters؛ لا تُسترجع system/tool messages. المهارات لا تُقصّ جزئيًا؛ يُضمَّن فقط ما يتسع داخل الميزانية.

## ما لا تعنيه الحدود

- هذه حدود أحرف وليست عدّ tokens؛ معدل تحويل النص إلى tokens يختلف حسب اللغة والمزود والموديل.
- لا توجد ضمانات بشأن عدد API requests التي ينفذها Hermes داخليًا أو Prompt caching لدى مزوده.
- لم نقسّم استهلاك Tokens الحقيقي أو تكلفة مزود؛ هذه البيانات تحتاج usage events من upstream.
- Worker وHermes وAI provider يظلون disabled افتراضيًا. لا يتم تشغيل runtime أو deploy في هذا العمل.

## اختبارات

اختبارات worker runtime تتحقق من حد المحادثة والمهارات، واختبار ذاكرة المستخدم يتحقق من الحد المشترك. النتائج تُسجل بعد CI فقط.
