# شرح سجل أحداث المحركات — SULY

## الفكرة

عندما يبدأ محرك مثل Hermes تنفيذ مهمة، لا يكفي أن نعرف النتيجة النهائية فقط. نحتاج سجلًا زمنيًا يوضح مراحل التنفيذ، لكن من دون حفظ محتوى خاص أو أوامر حساسة.

لذلك يفصل SULY بين نوعين من البيانات:

- **نتيجة المهمة:** تحفظ في سجل الخطوة بعد التحقق من ملكية العامل.
- **حدث التقدم:** يحفظ كبيانات وصفية محدودة مثل اسم الحدث ورقم التسلسل والتوقيت.

## مسار الحدث

1. Hermes يرسل حدثًا عبر SSE إلى العميل الموجود في hermes_agent.py.
2. _safe_run_event يتحقق من run_id ويقبل أسماء أحداث محددة فقط.
3. لا يُمرر النص أو reasoning أو tool arguments أو preview أو output.

4. HermesAgentAdapter يرسل metadata إلى EngineRunStore.append_event.
5. RPC باسم append_engine_run_event يتحقق مجددًا من أن worker ما زال يملك step lease وأن المحاولة ما زالت running.
6. الحدث يُحفظ في engine_run_events، ثم يعرضه GET /v1/tasks/{task_id} للمالك فقط.
7. شاشة تفاصيل المهمة تعرض اسم الحدث ووقت استلامه ورقم التسلسل، ولا تعرض payload من Hermes.

### حدود قراءة SSE

- أقصى حجم مجمّع للـ data هو 256 KiB، والحد الأقصى لطول السطر 65,536 حرفًا.
- لا يقبل parser أكثر من 64 سطر data في الحدث الواحد؛ يسقط الحدث حتى الفاصل التالي لتقييد كلفة الذاكرة، ثم يستأنف قراءة الأحداث التالية.
- الحدث الزائد لا يُعرض أو يُحفظ. قناة التقدم best-effort ولا تؤثر على نجاح المهمة أو فشلها.

## لماذا نعيد التحقق من lease في قاعدة البيانات؟

قد يفقد worker ملكية المهمة بينما اتصال SSE لا يزال مفتوحًا. لذلك لا نعتمد على فحص Python وحده. قاعدة البيانات هي المرجع النهائي: إذا انتهى lease أو تغيرت حالة المحاولة، يرفض RPC الحدث.

## منع التكرار

يستخدم الجدول unique index على (engine_run_id, event_seq) عندما يكون رقم التسلسل موجودًا. إذا أعاد Hermes إرسال نفس الحدث، لا ينشأ صف مكرر. وإذا تعارضت هوية الحدث مع التسلسل نفسه، لا يعتبر RPC التعارض نجاحًا.

## الصلاحيات

- المستخدم المسجل يستطيع قراءة أحداث سجلاته فقط عبر RLS.
- لا يستطيع المستخدم إدخال أو تعديل أو حذف الأحداث.
- الكتابة تتم من الخادم عبر service_role وRPC مخصص.
- لا تمر مفاتيح أو أسرار أو بيانات هوية إلى Hermes ضمن سجل الحدث.

## التفعيل والنشر

هذه إضافة قاعدة بيانات جديدة وليست مطبقة تلقائيًا. يجب تطبيق migration 20261120235000_engine_run_events.sql في قاعدة اختبار مؤقتة أولًا، والتحقق من RLS وRPC، ثم تطبيقها على staging قبل نشر API الذي يقرأ الجدول. لا يتم تفعيل Hermes أو worker بمجرد إضافة هذا السجل؛ إعدادات التشغيل تظل معطلة افتراضيًا.

## ما لا يفعله هذا النظام بعد

- لا يرسل الأحداث لحظيًا عبر WebSocket؛ شاشة المهمة تجدد بياناتها دوريًا.
- لا يخزن محتوى رسائل Hermes أو مخرجات الأدوات.
- لا يحل محل سجل التدقيق أو موافقات الأدوات.
- لا يثبت أن Hermes runtime يعمل أو أنه معزول فعليًا؛ ذلك يتطلب اختبار runtime مستقلًا.
