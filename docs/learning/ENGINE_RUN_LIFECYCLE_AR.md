# شرح تعليمي: دورة حياة تشغيل المحركات في SULY

هذا الدليل يشرح كيف يسجل SULY محاولة تشغيل محرك مثل Hermes، وكيف يمنع بقاء المحاولة معلقة إذا مات العامل أو انتهى lease الخاص بالخطوة.

## الملفات المرتبطة

- `services/api/app/services/engine_run_store.py`: يتصل بقاعدة البيانات عبر RPCs آمنة من الخادم.
- `services/api/app/worker_runtime.py`: يختار المحرك المسموح به ويشغله بعد التحقق من الموافقة.
- `services/api/app/services/task_worker.py`: يطالب بخطوة، يجدد lease، ثم يحفظ النتيجة أو الفشل.
- `supabase/migrations/20261120153000_engine_run_ledger.sql`: ينشئ جدول سجل المحاولات ودوال البدء والإنهاء.
- `supabase/migrations/20261120170000_engine_run_reconciliation.sql`: يغلق سجل المحاولة إذا انتهت الخطوة أو انتهى lease.

## المصطلحات

| المصطلح | معناه |
|---|---|
| Engine | محرك متخصص ينفذ قدرة مثل الوكيل أو البرمجة |
| Runtime | العملية التي تشغّل المحرك واعتمادياته |
| Task | المهمة الكاملة التي طلبها المستخدم |
| Step | خطوة واحدة داخل المهمة |
| Attempt | محاولة تنفيذ خطوة؛ يمكن أن تتكرر بعد فشل محدود |
| Lease | ملكية مؤقتة للخطوة يمنحها الخادم لعامل واحد |
| Lease token | رمز عشوائي يثبت أن العامل ما زال يملك الخطوة |
| Heartbeat | تجديد دوري لمدة الـlease أثناء التنفيذ |
| Reconciliation | مصالحة السجلات بعد فشل أو انقطاع غير متوقع |

## ماذا يحدث عند التشغيل الطبيعي؟

1. يطالب Worker بخطوة جاهزة من قاعدة البيانات.
2. قاعدة البيانات تمنحه lease token ووقت انتهاء.
3. يجدد Worker الـlease دوريًا حتى لا يأخذ عامل آخر الخطوة منه.
4. يتحقق SULY من موافقة المستخدم على تشغيل المحرك.
5. ينشئ `EngineRunStore` سجلًا بحالة `running`.
6. ينفذ المحرك عبر Engine Registry.
7. عند النجاح أو الفشل أو الإلغاء، يسجل SULY الحالة النهائية.
8. يحفظ Worker نتيجة الخطوة باستخدام lease token نفسه.

## ماذا يحدث إذا توقف العامل فجأة؟

قد يموت Worker أو تنقطع الشبكة قبل تسجيل نهاية المحاولة. عند انتهاء الـlease، تعيد آلية المطالبة بالمهام الخطوة إلى الانتظار أو تجعلها فاشلة إذا انتهت المحاولات.

الهجرة `20261120170000_engine_run_reconciliation.sql` تضيف Trigger داخل PostgreSQL. عندما تنتقل الخطوة من `running` إلى حالة أخرى، يبحث الـTrigger عن سجل المحاولة المطابق لنفس:

- معرف الخطوة.
- معرف المهمة.
- مالك المهمة.
- رقم المحاولة.

إذا كان السجل لا يزال `running`، يغلقه إلى `failed` أو `cancelled`. لا يغيّر السجلات التي انتهت بالفعل، ولا يلمس محاولة أحدث. ويستخدم رموز أخطاء آمنة فقط، فلا يخزن prompt أو مفاتيح أو مخرجات المحرك.

## لماذا نستخدم Trigger بدل مهمة تنظيف دورية؟

- المصالحة تتم في نفس معاملة تحديث الخطوة.
- لا نحتاج خدمة تنظيف منفصلة أو Cron مدفوع.
- لا توجد عملية حذف للسجلات.
- لا نغيّر حالة المهمة أو الخطوة من الـTrigger؛ هو يزامن سجل المحرك فقط.
- تظل قواعد lease هي المرجع الأساسي لملكية التنفيذ.

## حدود هذه المرحلة

- الهجرة موجودة في GitHub فقط حتى يتم تطبيقها على قاعدة Supabase.
- لا يعني ذلك أن Hermes أصبح مفعّلًا أو منشورًا.
- لا توجد حتى الآن هوية تشغيل خارجية upstream أو بث أحداث حي من Hermes.
- يجب إضافة اختبار تكامل PostgreSQL حقيقي قبل اعتبار هذه الآلية مثبتة على قاعدة الإنتاج.

## طريقة التعلم

ابدأ بقراءة `task_worker.py` ثم `engine_run_store.py` ثم `worker_runtime.py`. بعد ذلك اقرأ الهجرتين بالترتيب. شغّل اختبارات API المحلية أو عبر CI، ثم ارجع إلى هذا الدليل واربط كل خطوة بالملف الذي ينفذها.
