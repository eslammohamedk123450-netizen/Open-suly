# Hermes Agent capability integration plan and status

SULY intends to reuse Hermes Agent as its primary general-purpose agent runtime. This document maps Hermes capabilities to SULY's architecture; it is not a claim that all upstream features are currently enabled.

## Core capabilities to integrate

| Hermes capability | SULY destination | Integration status / boundary |
|---|---|---|
| Agent runtime / turn execution | Primary agent service | Runtime pinned, API disabled, not yet operational in SULY |
| Planning / tool selection | Hermes harness | Pending API and event lifecycle bridge |
| Skill discovery and invocation | Skill adapter / scoped workspace | Pending; skill files must be provenance checked and permission reviewed |
| Skill creation / revision | Versioned skill workspace | Pending; generated skills require review, tests and versioning before promotion |
| Persistent memory | Per-user isolated memory namespace | Pending; memory ownership, retention, deletion/export and isolation policy required |
| Session history and search | Conversation/session bridge | Pending; SULY remains authoritative for identity and tenant access |
| Tool calls | SULY capability registry | Pending; all privileged actions require server-side scopes, allowlists, audit and output caps |
| Delegation / subagents | SULY bounded subagent policy | Pending; concurrency, budget, depth, deadline and scope inheritance restrictions |
| Web search / content extraction | Web specialist tools | Pending; search results are untrusted input, URL and egress policies required |
| Browser automation | Browser Use/Skyvern adapter | Separate browser runtime; not enabled by Hermes bridge |
| Terminal / shell | Disposable execution sandbox | Explicitly blocked until sandbox hardening and egress controls are tested |
| File read/write/edit | Task-scoped workspace | Pending; no host filesystem or secrets mounts |
| MCP servers | SULY MCP broker | Pending; per-server allowlist, auth isolation, tool catalog review and approval gating |
| Provider/model routing | SULY AI gateway policy | Pending provider selection, no credentials configured |
| Multimodal/image tools | Capability-specific adapters | Pending; validate content limits, privacy and provider support |
| TTS/audio | Optional media adapter | Pending; explicit consent, rate/size limits and provider selection |

| Messaging/channel integrations | SULY channels | Not enabled; upstream gateway/channel ownership must not replace SULY auth |
| Remote execution backends | Sandbox provider adapter | Pending; only approved ephemeral providers, no credential leakage |

| Stop/cancel | SULY task cancellation | Worker now exposes cancel event on heartbeat/lease loss; upstream stop adapter pending |
| Retry/recovery/checkpoint | SULY durable DAG | SULY-owned retry and checkpoints; Hermes run mapping/idempotency pending |
| Health and metrics | SULY engine monitor | Pending; readiness must distinguish process health from model/tool capability |

## Required staged activation

1. **Sandbox first:** dedicate non-root container user; read-only root filesystem where compatible; disposable per-task workspace; CPU, memory, process and disk limits; no Docker socket; drop capabilities; no host mounts; network egress allowlist; redact logs. Verify actual upstream configuration and image behavior.
2. **API gate:** API server remains disabled until the exact upstream API/tool configuration is reviewed. A key alone is not sufficient safety.
3. **Run lifecycle bridge:** map SULY task+step+attempt to an idempotent Hermes run. Persist run reference server-side, poll or consume events, request upstream stop when cancellation/lease loss occurs, and bound all waits.
4. **Least-privilege tools:** expose only the initial reviewed toolset. Do not forward approval scopes as prompt text or grant Hermes its own access to SULY database.
5. **Skills and memory:** isolated per-user/project, with provenance, safe promotion, retention and delete/export semantics. Skills generated by an agent cannot silently self-grant permissions.
6. **Subagents:** maximum depth/concurrency, shared total token/time budget, allowlisted tools, no ambient identity or secret inheritance.
7. **Specialists:** add code and browser engines separately; Hermes may route but SULY authorizes and leases each specialist task.
8. **Verification:** adapter contract tests, API integration mocks, cancellation/lease-loss tests, sandbox smoke test, security/dependency/license scan, then optional real provider smoke test after user approval.

## Current verified implementation

- Upstream Hermes is pinned to commit `9f47677483d1b4de4d1a88d37b3b7ca18b18b215`.
- Compose profile is opt-in, no host port, and API server disabled.
- SULY bridge settings and bounded synchronous chat bridge exist. Base URL parsing rejects non-HTTP(S), missing-host, embedded credentials, query strings, and fragments before requests; invalid settings are covered by new tests. The worker now registers `hermes.agent.turn` as an approval-gated task operation (`agent.hermes.run`) with strict input-field and input/output size limits. The operation reaches the bridge only after the worker loads persisted approval scopes.
- Worker `run_once` accepts optional cancel-aware handlers. Lease loss/failure sets cancellation event and prevents result checkpoint.
- WorkerRuntime forwards the optional cancellation-aware handler interface.
- Unit tests for worker lease heartbeat and cancel-event behavior are authored but have not been executed in this environment.
- No Hermes container is built or started, no provider/model configured, and no real tool/agent execution is verified.

## Capability enablement policy

A capability is considered integrated only after code exists, required permissions are enforced, tests are run, and its intended runtime is actually started and verified. Documentation or upstream capability descriptions alone do not qualify as integration.

## Tool catalog API

Authenticated clients can now query `GET /v1/tools/approvals/catalog` to discover the currently registered worker operations. The response includes each tool's name, description, permission scope, approval requirement, and `approved` flag for the requesting user's active grants. This endpoint is descriptive only; it does not execute tools or grant/revoke permissions. Hermes remains disabled unless separately configured and sandbox-reviewed.

## Tool schema discovery

The authenticated tool catalog now publishes each registered tool's allowed and required input field names and the registry-enforced maximum serialized input/output byte sizes. This is metadata only: it does not relax the worker allow-list, change approval requirements, or expose arbitrary execution. Client-side forms can use this metadata for discovery while the server remains authoritative for validation.
