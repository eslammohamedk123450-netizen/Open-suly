# SULY — مسار النشر المجاني للاختبار

هذا المسار مخصص لاختبار التطبيق وسير المهام، وليس لاستضافة إنتاجية دائمة.

## مكونات المسار

- **API:** Render Free عبر ملف `render.yaml` في جذر المستودع.
- **Worker:** GitHub Actions عبر `.github/workflows/free-worker.yml`، يحاول معالجة قائمة المهام كل 5 دقائق، ويعمل بحد أقصى 230 ثانية في كل تشغيل.
- **Database/Auth:** مشروع Supabase الحالي؛ لا ننشئ قاعدة بيانات بديلة ولا ننقل بيانات.
- **Hermes وAI:** يظلان معطلين في هذا المسار. يمكن اختبار عملية `text.analyze` فقط إلى أن يتم إعداد محرك AI ومراجعة العزل الأمني.

## 1) إعداد Render من الهاتف

1. افتح https://render.com وسجّل الدخول باستخدام GitHub.
2. اختر **New → Blueprint** ثم اربط المستودع `eslammohamedk123450-netizen/Open-suly`.
3. اختر الفرع `main` وملف Blueprint الافتراضي `render.yaml`.
4. قبل النشر، أدخل قيم متغيرات البيئة الثلاثة المطلوبة:
   - `SUPABASE_URL`: عنوان مشروع Supabase.
   - `SUPABASE_PUBLISHABLE_KEY`: مفتاح Publishable الخاص بالمشروع.
   - `SUPABASE_SECRET_KEY`: المفتاح السري/Secret الخاص بالخادم فقط.
5. راجع أن الخطة **Free** ثم أنشئ الخدمة.
6. بعد اكتمال النشر، افتح رابط الخدمة وأضف `/health`. يجب أن يرجع JSON بحالة `ok`.

لا تضع المفتاح السري في Expo أو ملفات التطبيق أو GitHub repository variables العامة أو أي ملف داخل المستودع. أدخله فقط في إعدادات البيئة السرية للخدمة وGitHub Actions Secrets.

## 2) إعداد Worker عبر GitHub Actions

من صفحة المستودع على GitHub:

1. افتح **Settings → Secrets and variables → Actions → New repository secret**.
2. أضف السرّين التاليين:
   - `SUPABASE_URL`
   - `SUPABASE_SECRET_KEY`
3. افتح **Actions** وتأكد من تفعيل Actions للمستودع.
4. شغّل **SULY Free Test Worker → Run workflow** مرة يدويًا للتحقق من الإعداد.
5. بعد نجاح التشغيل اليدوي، سيحاول GitHub تشغيله تلقائيًا كل خمس دقائق.

إذا كان المستودع خاصًا، راجع إعدادات GitHub Actions وحدود الدقائق المجانية لحسابك. قد يتأخر تشغيل الجدولة أو لا يبدأ في موعده؛ لذلك لا تعتبره عاملًا دائمًا أو ضمانًا لزمن تنفيذ محدد.

## 3) ربط تطبيق Expo بالـAPI

في إعدادات بيئة بناء تطبيق العميل، عيّن:

```env
EXPO_PUBLIC_API_BASE_URL=https://YOUR-RENDER-SERVICE.onrender.com
```

استبدل القيمة بعنوان الخدمة الفعلي الذي يعطيه Render. هذا عنوان عام وليس سرًا. أعد بناء/نشر تطبيق العميل بعد ضبط المتغير، لأن متغيرات `EXPO_PUBLIC_*` تُضمّن في حزمة العميل.

## 4) اختبار حقيقي

1. سجّل الدخول بحساب SULY صالح.
2. افتح Agent Workspace.
3. أرسل عملية **Text Analysis** بنص تجريبي.
4. راقب حالة المهمة. قد تنتظر حتى تشغيل GitHub Actions التالي.
5. افتح سجل تشغيل **SULY Free Test Worker** في Actions عند الحاجة.
6. تأكد من ظهور النتيجة في التطبيق، ثم اختبر الإلغاء ومراجعة سجل المهمة.

## حدود المسار المجاني

- Render Free يوقف خدمة الويب بعد فترة خمول ويحتاج وقتًا للاستيقاظ؛ أول طلب قد يكون بطيئًا.
- GitHub Actions worker يعمل بدفعات قصيرة مجدولة، وليس 24/7. الجدولة best-effort وقد تتأخر.
- هذا ليس بديلًا عن عامل دائم، ولا يضمن تنفيذًا فوريًا أو مستمرًا.
- لا تشغّل Hermes أو أدوات shell/browser/filesystem على هذا المسار. Hermes API معطل، ويظل كذلك حتى تجهيز sandbox معزول ومراجعة أمنية.
- لا تستخدم هذا المسار لبيانات إنتاج حساسة أو مستخدمين حقيقيين على نطاق واسع.
- لا تضف بطاقة أو تفعّل أي خطة مدفوعة. إذا طلبت المنصة وسيلة دفع لإكمال التسجيل، توقف ولا تختَر موارد مدفوعة.

## التنظيف والإيقاف

- أوقف أو احذف خدمة Render من لوحة التحكم إذا لم تعد تحتاجها.
- أوقف جدولة Worker بحذف/تعطيل workflow أو تعطيل Actions للمستودع.
- احذف أسرار GitHub عند إيقاف الاختبار أو تدوير مفاتيح Supabase.
- عند تدوير المفتاح السري، حدّث سر GitHub ومتغير Render معًا.
